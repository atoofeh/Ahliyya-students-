# Android app

The Android app is the web client, packaged with [Capacitor 8](https://capacitorjs.com/) and given the
protections a browser cannot offer: the refresh token lives in the Android Keystore, and the window is
closed to screenshots and screen recording.

Package: `com.alahliyya.lms` · label: *Students Alahliyya* · `minSdk 24` (Android 7.0) · `targetSdk 36`.

---

## 1. Layout

Everything lives inside `client/`, so the repository is still two npm packages.

```
client/
  capacitor.config.json          appId, https scheme, keyboard/splash options
  resources/                     1024px icon sources + 2732px splash sources
  public/fonts/                  self-hosted woff2 + fonts.css
  android/                       generated by `cap add android`, then hand-edited:
    app/src/main/
      AndroidManifest.xml        no cleartext, no backup, FileProvider
      java/com/alahliyya/lms/
        MainActivity.java        registers LmsNative, sets FLAG_SECURE
        LmsNativePlugin.java     Keystore store · device id · openFile
      res/xml/network_security_config.xml     release: TLS only
    app/src/debug/res/xml/network_security_config.xml   debug: dev hosts only
    keystore.properties          release signing — gitignored, never committed
  src/
    api/native.js                the only module that imports @capacitor/*
    api/download.js              authenticated downloads, web + native
    app/shell.js                 back button, keyboard, system bars, splash
```

## 2. Prerequisites

| Tool | Version used | Note |
|---|---|---|
| JDK | 21 (`C:\Program Files\Android\openjdk\jdk-21.0.8`) | Gradle will not run on Java 24. Set `JAVA_HOME` to the JDK 21 path. |
| Android SDK | platform 36, build-tools 36.0.0 | Capacitor 8 requires `compileSdk 36`. |
| Node | 22 | |

`client/android/local.properties` must contain `sdk.dir=` pointing at the SDK. Use forward slashes:
`sdk.dir=C:/Users/<you>/AppData/Local/Android/Sdk`. A Windows path with single backslashes is an invalid
Java properties escape and fails with *"The filename, directory name, or volume label syntax is incorrect"*.

## 3. Build

```bash
cd client
npm run build:android          # vite build --mode android && cap sync android
npm run android:apk            # the above, then gradlew assembleDebug
```

`--mode android` loads `client/.env.android`, which holds the API address the packaged app talks to and
nothing else:

```
VITE_API_URL=http://192.168.1.115:5000/api/v1
```

**Point this at your server before shipping.** The current value is the development machine on the LAN,
so a phone on the same Wi-Fi can reach it. A production build must use `https://` — the release network
config rejects cleartext entirely, so an `http://` URL will simply fail to connect in a release APK.

Outputs:

| Artifact | Path |
|---|---|
| Debug APK | `client/android/app/build/outputs/apk/debug/app-debug.apk` |
| Release APK | `client/android/app/build/outputs/apk/release/app-release.apk` |
| Play bundle | `client/android/app/build/outputs/bundle/release/app-release.aab` |

## 4. Signing a release

Generate an upload key once, and keep it somewhere backed up. **Losing it means you can never update the
app on Play.**

```bash
keytool -genkeypair -v \
  -keystore /secure/path/alahliyya-upload.jks \
  -alias alahliyya-upload -keyalg RSA -keysize 4096 -validity 10000
```

Then create `client/android/keystore.properties` — gitignored, and it must stay that way:

```properties
storeFile=/secure/path/alahliyya-upload.jks
storePassword=…
keyAlias=alahliyya-upload
keyPassword=…
```

CI can instead set `LMS_KEYSTORE_FILE`, `LMS_KEYSTORE_PASSWORD`, `LMS_KEY_ALIAS` and `LMS_KEY_PASSWORD`.
With neither present, `assembleRelease` still succeeds and produces `app-release-unsigned.apk`, so a clean
checkout is never blocked.

```bash
cd client && npm run build:android
cd android && ./gradlew assembleRelease      # signed APK, for direct install
./gradlew bundleRelease                      # .aab, for Google Play
```

Verify what you are about to publish:

```bash
$ANDROID_HOME/build-tools/36.0.0/apksigner verify --print-certs app-release.apk
```

`minifyEnabled` is deliberately **false**. R8 would shrink the package, but Capacitor resolves plugins
reflectively; enabling it requires testing every plugin path on a device first.

## 5. The secret scan — run this before every release

An APK is world-readable. Anyone who installs it can unzip it and read every byte, so nothing from
`server/.env` may be inside it.

```bash
node scripts/scan-apk-secrets.mjs [apk] [envfile]
```

It unpacks the package and searches every entry — DEX, `resources.arsc`, resources, assets and the packaged
web bundle — in both UTF-8 and UTF-16, for every value in `server/.env` whose **name** matches
`SECRET|PASSWORD|_PASS|_KEY|TOKEN|_URI|DSN`. Selecting by name pattern rather than a fixed list means a
secret added to the env later is covered without anyone remembering to update the scanner. Exit code 1
means a leak; the CI job treats that as a failed build.

## 6. What the native layer does

### `LmsNativePlugin.java`

| Method | Behaviour |
|---|---|
| `secureSet` / `secureGet` / `secureRemove` | AES-256-GCM. The key is generated inside the AndroidKeyStore and cannot be exported; the value is stored as `base64(iv):base64(ciphertext)` in private SharedPreferences. Undecryptable ciphertext (device restored, app data cleared) is dropped rather than wedging the login. |
| `deviceId` | SHA-256 of `Settings.Secure.ANDROID_ID`, hashed on the device so the raw platform id never crosses the bridge or the network. Falls back to a Keystore-stored UUID when `ANDROID_ID` is missing or the known-buggy `9774d56d682e549c`. |
| `openFile` | Serves a cached download to the system viewer through the `FileProvider`, with a one-shot read grant. |

Because the device id derives from `ANDROID_ID`, **reinstalling the app keeps the same device binding** —
a reinstall does not need an administrator device reset. Clearing app data alone likewise keeps it.
A factory reset changes it, and then the student does need a reset from the Security Center.

### Session transport

The server already distinguishes native clients by `x-client-platform` (`auth.controller.js`). On Android
the app sends `android`, receives the refresh token in the response body as well as the cookie, and stores
that copy in the Keystore. `withCredentials` is off on native: the WebView runs on its own origin
(`https://localhost`), so cookies to the API host are cross-site and unreliable. `ALLOWED_ORIGINS` on the
server must therefore include `https://localhost` (and `capacitor://localhost` for a future iOS build).

### Shell

`src/app/shell.js` installs the back-button, keyboard and splash behaviour, and is a no-op in a browser.
Back closes the topmost open layer first — any `Modal`, or the course player's curriculum sheet, registers
itself with `pushBackHandler` — then goes back in history, then asks for a second press to exit.
The Capacitor plugin modules are imported dynamically so the web bundle never carries them.

### Phone notifications — and what they cannot do

`src/api/deviceNotifications.js` posts a real notification into the phone's
notification shade whenever the unread count grows: `NotificationsBell` already
polls `/notifications/unread-count` every 30 seconds, and when that number goes
up it fetches the new items and hands them to `@capacitor/local-notifications`.
Tapping one opens the app on the linked screen. Permission (`POST_NOTIFICATIONS`
on Android 13+) is requested the first time there is something to show, not on a
cold start, and a refusal is never re-asked during the session. The plugin is
imported dynamically, so the web bundle does not carry it and the whole module
is inert in a browser.

**This is a local notification, not a push.** The app posts it itself; nothing
about a question or a course leaves the device to a third-party service, and no
Google project is involved. The price is that it only fires while the app
process is alive — open, or recently backgrounded. **With the app fully closed
or swept away, no notification arrives.**

Delivering those requires Firebase Cloud Messaging: a (free) Firebase project,
its `google-services.json` in `client/android/app/`, the FCM server key held as
a server secret, a device-token registration endpoint, and a sender in the
notification service. Nothing here blocks that — it is additive — but it cannot
be built without the Google project, which only the platform owner can create.

### Safe areas

`index.html` carries `viewport-fit=cover`, and Capacitor's built-in `SystemBars` plugin publishes
`--safe-area-inset-top/right/bottom/left` on `<html>`. `index.css` turns those into two **additive**
utilities, `pt-safe` and `pb-safe`, that add the inset on top of whatever padding the element already
wanted — a plain `padding-bottom: env(...)` utility would override Tailwind's `p-4` and collapse to zero
on every device without an inset. Left/right insets are applied once, on the shell's root element.

Capacitor only goes edge-to-edge when the device's Android System WebView is **version 140 or newer**;
below that it lets the system inset the WebView instead, because older WebViews report safe-area values
incorrectly. On such a device the insets read `0px` and the layout is still correct — the WebView simply
never extends under the system bars. Both paths were exercised: the emulator used in §7 runs WebView 133,
so it takes the inset path, and the header's computed `padding-top` stayed at its designed `10px`.
