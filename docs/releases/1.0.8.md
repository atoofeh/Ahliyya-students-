# Feker 1.0.8

Prepared November 19, 2026 (Asia/Amman).

## Changes

- Video link renewal restores the current position, play/pause state, speed and volume after metadata/seek completion. Reloads no longer reapply the lesson's original resume point or save a loading-generated zero position. Failed renewals retry, and interrupted playback offers a visible retry action.
- HTTP streaming correctly handles suffix and open-ended byte ranges while preserving token/session checks and encrypted storage.
- Teachers can click curriculum lesson titles for an authorized preview. Video previews do not write student progress; text, documents, quiz summaries and assignment summaries are supported. Editing fetches the complete lesson so curriculum summaries cannot erase text. Duration can be cleared while typing and defaults to zero only on save.
- Course and global announcements accept raster photos through the existing authenticated/scanned file routes. Publishing shows upload/sending progress and blocks repeated clicks. A unique per-author request ID prevents duplicate announcements and notification fan-out on retries.
- Returning from course management preserves the originating staff course list, search and page, including for the owner.
- Temporary network/server failures no longer discard a remembered native login. Token rotation keeps its persistence mode; returning online retries session restoration.
- Video chunk uploads cancel and settle outstanding workers before retry/resume, retry transient errors with a bounded delay, and finalize only once. The server validates chunk lengths, installs complete chunks atomically, deduplicates inventory, and handles assembly/encryption stream errors.

## iOS handoff

The project is prepared as version `1.0.8`, build `12`; its web assets have been built and synchronized locally. Installed Apple apps receive the player fix through an updated app build. Website deployment does not replace their embedded web bundle.

On the Mac, pull this release, run `npm ci` and `npm run build:ios` in `client`, then open `npm run ios:open`. Verify the version/build against App Store Connect, exercise playback past at least two renewals on a real iPhone, and archive/sign/upload with Xcode. No signed iOS archive or App Store submission can be produced by the Windows build.

## Deployment boundaries

Deploy the website build in production mode (same-origin `/api/v1`), retain old hashed assets for already-open clients, and replace the HTML entry last. Deploy only the changed video/announcement server modules and announcement model, then restart the API. Verify the `author_1_requestId_1` partial unique index before relying on concurrent publish deduplication.

No media/key rotation, storage move, enrollment change, account reset or database migration is required. Record actual production verification in `docs/SERVER_CONTEXT.md` after deployment.
